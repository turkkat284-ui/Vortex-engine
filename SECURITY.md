# Security Policy

If you discover a security vulnerability in this project, thank you for reporting it responsibly. To help us resolve issues quickly and privately, please follow the reporting guidance below.

## Reporting a Vulnerability

Please report security issues privately and responsibly. Do not open a public issue for a vulnerability.

Preferred reporting methods:
- GitHub Security Advisories (preferred)
- Email: turkkat@gmail.com

When reporting, please include:
- A clear summary of the issue and its potential impact.
- Detailed steps to reproduce, including commands and environment/version information.
- Proof of concept or exploit code if available.
- Any mitigation or workaround you have already tested.

Do not disclose the vulnerability publicly until it has been addressed and a safe remediation is available.

## Response Process

- We will acknowledge receipt of your report as soon as possible.
- We will assess the issue and determine whether it is valid and exploitable.
- We aim to provide an initial response quickly and to coordinate a fix when needed.
- If the issue is confirmed, we will work with you on a coordinated disclosure timeline.

## Safe Harbor

We appreciate responsible security research. If you follow this policy and act in good faith to avoid unauthorized access, data destruction, or disruption of services, we will not pursue legal action against you.

## Disclosure Policy

We prefer coordinated disclosure. Once a fix is available and users can safely update, we may publish a public advisory or release note describing the issue and remediation.
